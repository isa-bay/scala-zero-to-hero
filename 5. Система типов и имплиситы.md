### Иерархия типов

Scala строится на единой иерархии типов. На вершине — `Any`, от которого расходятся две ветви:

- **`AnyVal`** — базовый тип для всех «значимых» типов, соответствующих примитивам JVM (`Int`, `Double`, `Boolean`, `Char`, `Unit` и т.д.). Они наследуют `AnyVal` и реализованы как value-классы.
- **`AnyRef`** — аналог `java.lang.Object`, базовый тип для всех ссылочных типов (строки, коллекции, пользовательские классы).

Снизу иерархию замыкают:
- **`Nothing`** — нижний тип, подтип абсолютно любого типа. Не имеет значений. Используется для сигнализации о невозвратности (исключения, бесконечные циклы) и в параметризованных типах (например, `Nil` имеет тип `List[Nothing]`).
- **`Null`** — тип с единственным значением `null`. Является подтипом всех ссылочных типов (AnyRef-наследников). На практике `null` стараются избегать в пользу `Option`.

`Unit` — особый тип, аналог `void`, с единственным значением `()`. Относится к `AnyVal`. Функции, возвращающие `Unit`, выполняются ради побочных эффектов.

Связь с Java:
- `AnyRef` мапится в `java.lang.Object`.
- Значимые типы `AnyVal` компилируются в примитивы JVM, где возможно, или в обёртки (`Int` → `int`/`Integer`).
- `Nothing` и `Null` существуют только на уровне компиляции и не имеют прямых аналогов в байт-коде.

### Параметрический полиморфизм (generics)

#### Обобщённые классы и методы
Классы и методы могут быть параметризованы типами, что позволяет писать универсальный, типобезопасный код.

```scala
class Box[A](val value: A)

def identity[T](x: T): T = x
```

#### Стирание типов (type erasure) и его последствия
Как и в Java, информация о generic-параметрах стирается на этапе компиляции. В байт-коде `Box[Int]` и `Box[String]` — это один и тот же класс `Box`. Это приводит к:

- Невозможности различить generic-типы в паттерн-матчинге (например, `case list: List[Int]` не отличит список целых от списка строк во время выполнения; компилятор предупредит).
- Необходимости передавать `ClassTag`/`TypeTag` (Scala 2) или использовать `TypeTest`/`ClassTag` (Scala 3) для работы с массивами и проверкой типов.

Пример с `ClassTag` в Scala 2/3 (остаётся для совместимости):
```scala
import scala.reflect.ClassTag

def makeArray[T: ClassTag](length: Int): Array[T] = new Array[T](length)
```

### Вариантность

Вариантность определяет, как наследование между параметризованными типами соотносится с наследованием их типовых аргументов.

- **Инвариантность** (по умолчанию): `Box[Cat]` не является подтипом ни `Box[Animal]`, ни `Box[Any]`, даже если `Cat <: Animal`. Безопасно для чтения и записи.
- **Ковариантность** (`+T`): `Producer[Cat]` является подтипом `Producer[Animal]`. Позволяет использовать более конкретный тип в позиции, где ожидается более общий. Применяется к типам, которые только отдают значения (выход). Пример: `List[+A]`.
- **Контравариантность** (`-T`): `Consumer[Animal]` является подтипом `Consumer[Cat]`. Используется для типов, которые только принимают значения (вход). Пример: `Ordering[-T]`, обработчики событий.

Правило PECS (Producer Extends, Consumer Super) помогает запомнить: если тип только производит значения — ковариантность (`+`), если только потребляет — контравариантность (`-`). Если и то, и другое — инвариантность.

```scala
class Co[+A]    // ковариантный
class Contra[-A] // контравариантный

val co: Co[Animal] = Co[Cat]()          // работает
val contra: Contra[Cat] = Contra[Animal]() // работает
```

Компилятор проверяет корректность использования вариантных параметров в теле класса, запрещая использование ковариантного типа в контравариантной позиции (например, параметр метода) и наоборот.

### Ограничения типов

Ограничения сужают множество допустимых типовых аргументов.

- **Верхняя граница** `A <: B` — `A` должен быть подтипом `B`.
  ```scala
  def max[A <: Ordered[A]](x: A, y: A): A = if x > y then x else y
  ```
- **Нижняя граница** `A >: B` — `A` должен быть супертипом `B`. Часто встречается в объявлениях методов, где нужно сохранить вариантность.
  ```scala
  def prepend[B >: A](elem: B): List[B] = elem :: this
  ```
- **Контекстные границы** `A : Ordering` — требуют наличия неявного (given) значения типа `Ordering[A]`. В Scala 2: `[A: Ordering]`. В Scala 3: `[A: Ordering]` или `using`.
  ```scala
  def sort[A: Ordering](list: List[A]): List[A] = list.sorted
  ```

### Абстрактные члены типов (`type`)

В трейтах и классах можно объявить абстрактный тип, который будет конкретизирован в наследниках. Это альтернатива параметризации типа.

```scala
trait Reader:
  type Input
  def read(source: Input): String

class FileReader extends Reader:
  type Input = java.io.File
  def read(file: java.io.File): String = scala.io.Source.fromFile(file).mkString
```

Абстрактные типы могут иметь ограничения:
```scala
trait Container:
  type A <: AnyRef
```

Абстрактные типы позволяют описывать сложные отношения внутри иерархии без протаскивания типовых параметров через все сигнатуры.

### Имплиситы в Scala 2

В Scala 2 механизм неявных (implicits) включает три основные возможности: неявные параметры, неявные преобразования и неявные классы.

#### Неявные параметры и значения
Параметр метода, помеченный `implicit`, заполняется компилятором из области видимости по типу.

```scala
def greet(name: String)(implicit greeting: String): String = s"$greeting, $name"

implicit val defaultGreeting: String = "Hello"
println(greet("Alice")) // Hello, Alice
```

Поиск неявных значений происходит в:
- Сопутствующем объекте (companion) типа.
- Сопутствующих объектах типов, участвующих в сигнатуре.
- Текущей области видимости (локальные, импортированные, пакетные объекты).

При конфликте компилятор выбирает наиболее конкретное значение; при неоднозначности — ошибка.

#### Неявные преобразования (`implicit def`)
Метод, помеченный `implicit`, преобразует один тип в другой автоматически. Используется для «обогащения» существующих типов (extension methods) или адаптации. В Scala 2 неявные преобразования требуют импорта `scala.language.implicitConversions`.

```scala
implicit def stringToInt(s: String): Int = Integer.parseInt(s)
val x: Int = "123" // неявное преобразование
```

#### Неявные классы (`implicit class`)
Позволяют добавлять методы к существующим типам без изменения их кода. Компилятор оборачивает экземпляр в новый класс.

```scala
implicit class StringOps(s: String):
  def shout: String = s.toUpperCase + "!"

println("hello".shout) // HELLO!
```

Неявный класс должен быть определён внутри другого объекта, класса или трейта, а его конструктор может принимать ровно один неявный параметр (оборачиваемый объект).

#### Приоритеты и разрешение неоднозначностей
Чтобы контролировать приоритеты, используется линейка наследования трейтов: более приоритетные экземпляры помещаются в подклассы. При импорте имплиситы из объектов-компаньонов имеют более низкий приоритет, чем локальные.

### Given/Using в Scala 3

Scala 3 заменяет имплиситы на более явные и структурированные конструкции.

#### `given` определения
`given` определяет «каноническое» значение заданного типа, доступное для неявной передачи.

```scala
given defaultGreeting: String = "Hello"
```

Можно определить анонимный given без имени:
```scala
given Int = 42
```

#### `using` параметры
Вместо `implicit` для параметров используется `using`. Компилятор ищет given-значения подходящего типа.

```scala
def greet(name: String)(using greeting: String): String = s"$greeting, $name"

println(greet("Alice")) // найдет given String
```

#### `summon` для явного вызова
Функция `summon[T]` (аналог `implicitly[T]` в Scala 2) позволяет явно получить текущее given-значение типа `T`.

```scala
val greeting = summon[String]
```

#### Импорт и область видимости
Given-значения импортируются как обычные члены. Можно импортировать все given-ы из объекта:
```scala
import MyDefaults.given
```
Или конкретные по имени/типу.

Поиск given аналогичен правилам implicits, но синтаксис унифицирован.

### Расширяющие методы (Extension methods)

#### `implicit class` в Scala 2
Расширение существующих типов достигается через неявные классы (см. выше). Это основной способ добавления новых методов к типам, не подвластным изменению.

#### `extension` в Scala 3
В Scala 3 введён прямой синтаксис для extension-методов без необходимости создавать неявные классы.

```scala
extension (s: String)
  def shout: String = s.toUpperCase + "!"
  def greet(prefix: String): String = s"$prefix $s"

println("hello".shout)           // HELLO!
println("world".greet("Hello"))  // Hello world
```

Можно параметризовать расширение:
```scala
extension [T](list: List[T])
  def second: Option[T] = list.drop(1).headOption
```

Этот подход улучшает читаемость и делает компиляцию быстрее.

### Тайпклассы (Type classes)

Тайпкласс — паттерн, реализующий ad-hoc полиморфизм: возможность определять поведение для типов без изменения самих типов. Состоит из:

1. **Трейт-тайпкласс** — параметризованный трейт с набором операций.
2. **Экземпляры** — `given`/`implicit` реализации для конкретных типов.
3. **Использование** — методы с `using`/`implicit` параметрами, ограниченные контекстной границей.

Пример `Show`:
```scala
trait Show[A]:
  def show(a: A): String

given Show[Int] with
  def show(a: Int) = a.toString

given Show[String] with
  def show(a: String) = s""""$a""""

def printIt[A](a: A)(using s: Show[A]): Unit = println(s.show(a))

printIt(42)      // 42
printIt("hello") // "hello"
```

Часто используют контекстную границу и `summon`:
```scala
def printIt[A: Show](a: A): Unit = println(summon[Show[A]].show(a))
```

#### Автоматический вывод (deriving) в Scala 3
Для простых тайпклассов (таких как `Eq`, `Ordering`, `Show`) Scala 3 поддерживает `derives`, автоматически генерирующий экземпляры для case-классов и перечислений.

```scala
import scala.deriving.Mirror

trait Eq[T]:
  def eqv(x: T, y: T): Boolean

object Eq:
  given Eq[Int] with
    def eqv(x: Int, y: Int) = x == y
  // автоматический вывод через макросы
  inline def derived[T](using m: Mirror.Of[T]): Eq[T] = ???
```

На практике можно использовать библиотеку `circe` для JSON, где `Encoder` и `Decoder` выводятся с помощью `derives` или `given`-макросов.

#### Примеры тайпклассов
- `Ordering` — сравнение (встроен в стандартную библиотеку).
- `Numeric` — арифметические операции.
- `Encoder`/`Decoder` — сериализация (Circe, ZIO JSON).
- `Show`, `Eq` из Cats.
- `Monoid`, `Functor` и другие — из библиотек функционального программирования.

### Продвинутые возможности типов

#### Self-types (самоссылочные типы)
Self-type задаёт требование, что класс или трейт может быть подмешан только к типам, удовлетворяющим определённому типу. Записывается как `this: Тип =>`.

```scala
trait UserService:
  def getUser(id: Int): String

trait UserComponent:
  this: UserService =>   // требует наличия UserService
  def printUser(id: Int): Unit = println(getUser(id))
```

Позволяет реализовать паттерн «торт» (cake pattern) и обеспечивает композицию без наследования.

#### Phantom types (фантомные типы)
Фантомный тип — типовой параметр, который не используется в значениях времени выполнения, но несёт информацию на уровне типов для ограничения операций.

```scala
trait Locked
trait Unlocked

class Door[State](private val name: String):
  def open(using State =:= Unlocked): String = s"$name opened"
  def lock: Door[Locked] = Door[Locked](name)

val unlockedDoor = Door[Unlocked]("Front")
unlockedDoor.open   // работает
// Door[Locked]("Back").open // ошибка компиляции
```

#### Зависимые от пути типы (path-dependent types)
Тип может зависеть от конкретного экземпляра, а не только от класса. Например, внутренний тип класса.

```scala
class Database:
  class Connection:
    def query(q: String): String = "result"

val db1 = Database()
val db2 = Database()
val conn1: db1.Connection = db1.Connection()
// val conn2: db1.Connection = db2.Connection() // ошибка
```

Используется для реализации типобезопасных DSL и гетерогенных списков.

#### Opaque типы (Scala 3)
Прозрачные на уровне определений, но скрывающие внутреннее представление от внешнего мира. Позволяют создавать newtype без накладных расходов времени выполнения.

```scala
object Money:
  opaque type USD = BigDecimal
  object USD:
    def apply(value: BigDecimal): USD = value
    extension (usd: USD) def amount: BigDecimal = usd

import Money.USD
val price = USD(100)   // тип USD
// price + 1           // ошибка: USD не является BigDecimal
price.amount + 1       // работает через extension
```

При компиляции `USD` стирается до `BigDecimal`, поэтому нет boxing.

#### Union и Intersection типы (Scala 3)
- **Union types** `A | B` — значение может быть любого из перечисленных типов.
  ```scala
  def stringify(x: Int | String): String = x match
    case i: Int => i.toString
    case s: String => s
  ```
- **Intersection types** `A & B` — значение одновременно удовлетворяет обоим типам. Полезно для композиции трейтов.
  ```scala
  trait Resettable:
    def reset(): Unit
  trait Loggable:
    def log(): Unit

  def useBoth(obj: Resettable & Loggable): Unit =
    obj.reset()
    obj.log()
  ```

#### Match types (Scala 3)
Match types позволяют определять преобразования на уровне типов подобно вычислениям на значениях.

```scala
type Elem[X] = X match
  case String => Char
  case Array[t] => t
  case Iterable[t] => t

val c: Elem[String] = 'A'
val i: Elem[Array[Int]] = 42
```

Используются для рекурсивных типов, гетерогенных списков и тайпклассовых дериваций.

#### Type lambdas
Type lambda — анонимная функция на типах. В Scala 2 использовалась конструкция `({ type L[A] = ... })#L`. В Scala 3 добавлен нативный синтаксис:

```scala
type FunctorLike = [F[_]] =>> [A, B] => (A => B) => F[A] => F[B]
```

Чаще всего type lambdas применяются в библиотеках для частичного применения типовых конструкторов, например, в Cats для определения экземпляров тайпклассов для типов с «дырками» (Either, Map).

```scala
import cats.Monad
type EitherStr[A] = Either[String, A]
val monad = summon[Monad[EitherStr]]  // работает благодаря type lambda в инстансе
```

Это мощный инструмент при работе с типами высших родов (higher-kinded types)
