### Функции как значения первого класса

Функции в Scala — это полноценные объекты, которые можно присваивать переменным, передавать в качестве аргументов и возвращать из других функций.

#### Анонимные функции (лямбды): синтаксис `(x: Int) => x + 1`
Лямбда-выражение определяет функцию без имени. Синтаксис: `(параметры) => тело`. Если тип параметров выводится контекстом, аннотацию типа можно опустить.

```scala
val increment = (x: Int) => x + 1
val sum = (a: Int, b: Int) => a + b
```

Когда параметр один и тип очевиден, можно использовать сокращённую запись с подстановочным знаком `_` (placeholder syntax):
```scala
val double: Int => Int = _ * 2   // эквивалентно (x: Int) => x * 2
```

#### Типы функций: `FunctionN[A, B, ...]`, синтаксический сахар `A => B`
Тип функции `A => B` — это синтаксический сахар для трейта `scala.Function1[A, B]`. Для функций с большим числом аргументов существуют `Function2`, `Function3` и т.д. (до 22 в Scala 2, в Scala 3 ограничений нет).  
`=>` ассоциативно вправо: `A => B => C` эквивалентно `A => (B => C)` — это функция, возвращающая другую функцию.

```scala
val f: Int => String = n => s"Число $n"
val g: Function1[Int, String] = f   // то же самое
```

#### Eta-расширение: метод в функциональное значение
Методы (`def`) в Scala не являются значениями, но могут быть автоматически преобразованы в функциональный объект при необходимости. Это называется eta-расширением. В Scala 3 расширение происходит автоматически, если метод используется там, где ожидается функция.

```scala
def add(x: Int, y: Int): Int = x + y
val adder: (Int, Int) => Int = add   // автоматическое eta-расширение
```

В Scala 2 для явного преобразования метода в функцию используется `_` после имени метода: `val adder = add _`.

### Функции высшего порядка

Функция высшего порядка принимает функцию в качестве параметра и/или возвращает функцию как результат.

#### Приём функций в параметры и возврат функций
```scala
def operate(x: Int, f: Int => Int): Int = f(x)

val result = operate(5, x => x * x)   // 25
```

Возврат функции:
```scala
def multiplier(factor: Int): Int => Int = (x: Int) => x * factor

val times3 = multiplier(3)
println(times3(10))  // 30
```

#### Стандартные операции коллекций: `map`, `flatMap`, `filter`, `foreach`
- **`map`** — применяет функцию к каждому элементу, возвращает новую коллекцию.
  ```scala
  val doubled = List(1, 2, 3).map(_ * 2)  // List(2, 4, 6)
  ```
- **`flatMap`** — применяет функцию, возвращающую коллекцию, и «сплющивает» результат.
  ```scala
  val chars = List("ab", "cd").flatMap(_.toList)  // List('a', 'b', 'c', 'd')
  ```
- **`filter`** — отбирает элементы, удовлетворяющие предикату.
  ```scala
  val evens = List(1, 2, 3, 4).filter(_ % 2 == 0)  // List(2, 4)
  ```
- **`foreach`** — выполняет побочное действие для каждого элемента, возвращает `Unit`.
  ```scala
  List(1, 2, 3).foreach(x => println(x))
  ```

#### Свёртки: `foldLeft`, `foldRight`, `reduce`, `scan`
Свёртки последовательно обрабатывают элементы коллекции с накоплением результата.

- **`foldLeft`** — левая свёртка, проходит слева направо.
  ```scala
  val sum = List(1, 2, 3).foldLeft(0)((acc, x) => acc + x) // 6
  ```
- **`foldRight`** — правая свёртка (справа налево). Имеет значение для бесконечных или ленивых структур.
  ```scala
  val concat = List("a", "b", "c").foldRight("")((x, acc) => x + acc) // "abc"
  ```
- **`reduce`** — свёртка без начального значения, применяется к непустым коллекциям.
  ```scala
  val product = List(2, 3, 4).reduce(_ * _) // 24
  ```
- **`scan`** — как `fold`, но возвращает коллекцию всех промежуточных состояний аккумулятора.
  ```scala
  val partialSums = List(1, 2, 3).scanLeft(0)(_ + _) // List(0, 1, 3, 6)
  ```

### Каррирование и частичное применение

#### Каррированные функции: несколько списков параметров
Каррированная функция — это функция с несколькими группами параметров. Она возвращает новую функцию после каждого списка аргументов.

```scala
def curriedAdd(x: Int)(y: Int): Int = x + y

val addFive = curriedAdd(5)   // y => 5 + y
println(addFive(10))          // 15
```

Каррирование упрощает создание специализированных функций и улучшает читаемость при передаче функциональных аргументов.

#### Частичное применение: фиксация части аргументов
Можно зафиксировать часть аргументов, получив функцию от оставшихся параметров. Для этого используется подстановочный знак `_` на месте неприменяемых аргументов.

```scala
def format(prefix: String, value: Int, suffix: String): String =
  s"$prefix$value$suffix"

val prefixWithZero: (Int, String) => String = format("ID:", _, _)
println(prefixWithZero(42, "!"))  // ID:42!
```

Для каррированных функций частичное применение происходит естественным образом: `curriedAdd(5)` уже является функцией `Int => Int`.

#### Преобразование методов в функции с помощью `_`
В Scala 2 для превращения метода в функциональное значение использовался `_`. В Scala 3 eta-расширение происходит автоматически, но `_` всё ещё может использоваться для частичного применения.

```scala
def greet(name: String) = s"Hello, $name"
val greetFn = greet _   // функция (в Scala 2 явно, в Scala 3 не обязательно)
```

### Замыкания (closures)

#### Захват переменных из окружающей области видимости
Замыкание — это функция, которая ссылается на свободные переменные из внешнего контекста. Эти переменные «захватываются» и остаются доступными даже после выхода из области, где они были определены.

```scala
def makeCounter(initial: Int): () => Int =
  var count = initial
  () => {
    count += 1
    count
  }

val counter = makeCounter(10)
println(counter()) // 11
println(counter()) // 12
```

#### Отличие val и var в замыканиях
Захваченная `var` может изменяться как внутри замыкания, так и снаружи, что делает функцию нечистой и создаёт побочные эффекты. Захваченное неизменяемое `val` всегда имеет одно значение — это безопасно и предпочтительно в функциональном стиле.

```scala
var external = 0
val inc = () => { external += 1; external }  // мутирует внешнюю переменную

val immutableRef = 42
val readOnly = () => immutableRef + 1      // чистая функция
```

### Рекурсия и хвостовая рекурсия

#### Обычная рекурсия
Функция вызывает саму себя с новыми аргументами, пока не достигнет базового случая. Каждый вызов занимает стековый кадр, поэтому глубокая рекурсия может привести к `StackOverflowError`.

```scala
def factorial(n: Int): BigInt =
  if n <= 1 then 1
  else n * factorial(n - 1)
```

#### Аннотация `@scala.annotation.tailrec`
Хвостовая рекурсия — это когда вызов функцией самой себя является последней операцией (не требует сохранения промежуточных вычислений в стеке). Компилятор может оптимизировать такую рекурсию в цикл, избегая переполнения стека. Аннотация `@tailrec` заставляет компилятор проверить, действительно ли рекурсия хвостовая.

```scala
import scala.annotation.tailrec

@tailrec
def factorialTail(n: Int, accumulator: BigInt = 1): BigInt =
  if n <= 1 then accumulator
  else factorialTail(n - 1, n * accumulator)
```

Если метод не удовлетворяет условиям хвостовой рекурсии, компилятор выдаст ошибку.

#### Преобразование в цикл компилятором
При обнаружении хвостовой рекурсии компилятор Scala заменяет рекурсивные вызовы на итеративный цикл в байт-коде, поэтому исполнение не расходует стек для каждого шага. Это позволяет писать рекурсивные алгоритмы в функциональном стиле без потери производительности.

### Иммутабельность

#### Преимущества неизменяемых данных
- **Безопасность в многопоточной среде**: неизменяемые объекты можно свободно разделять между потоками.
- **Простота рассуждений**: значение не меняется после создания, что исключает неожиданные побочные эффекты.
- **Лёгкость тестирования и отладки**.
- **Сохранение истории версий**: можно безопасно кэшировать предыдущие состояния.

#### Создание обновлённых копий (например, `copy` у case-классов)
Вместо мутирования существующего объекта создаётся новый с изменёнными полями. Case-классы предоставляют метод `copy`:

```scala
case class Person(name: String, age: Int)

val alice = Person("Alice", 25)
val olderAlice = alice.copy(age = 26)
```

Для коллекций существуют методы, возвращающие новые коллекции: `:+` и `+:` добавляют элементы к `List`, `updated` заменяет элемент по индексу.

#### Работа с вложенными неизменяемыми структурами (линзы — обзор)
При глубокой вложенности обновление вложенных полей через `copy` становится громоздким. Оптические линзы — это композируемые геттеры и сеттеры для неизменяемых данных. Библиотеки, такие как **Monocle**, предоставляют удобный DSL:

```scala
case class Address(street: String, city: String)
case class Person(name: String, address: Address)

import monocle.Lens
val addressLens: Lens[Person, Address] = Lens[Person, Address](_.address)(a => p => p.copy(address = a))
val cityLens: Lens[Address, String] = Lens[Address, String](_.city)(c => a => a.copy(city = c))
val personCityLens = addressLens.andThen(cityLens)

val p = Person("Bob", Address("Main St", "NYC"))
println(personCityLens.modify(_ + "!")(p)) // Person(Bob,Address(Main St,NYC!))
```

Линзы позволяют работать с неизменяемыми данными элегантно, не жертвуя функциональностью.

### Композиция функций

#### `compose`, `andThen`
Эти методы позволяют создавать новые функции путём объединения существующих.

- **`f.andThen(g)`** — применяет сначала `f`, затем `g`. То есть: `(x => g(f(x)))`.
- **`f.compose(g)`** — применяет сначала `g`, затем `f`: `(x => f(g(x)))`.

```scala
val addOne = (x: Int) => x + 1
val double = (x: Int) => x * 2

val addThenDouble = addOne.andThen(double)
println(addThenDouble(3)) // (3+1)*2 = 8

val doubleThenAdd = addOne.compose(double)
println(doubleThenAdd(3)) // (3*2)+1 = 7
```

#### Цепочки преобразований
Функциональный стиль поощряет построение конвейеров данных через последовательные вызовы функций. Это улучшает читаемость и поддержку:

```scala
val result = List(1, 2, 3, 4)
  .filter(_ % 2 == 0)
  .map(_ * 10)
  .foldLeft("")((acc, x) => s"$acc $x")
// " 20 40"
```

Композицию функций можно использовать и вне коллекций, например, для построения middleware-обработчиков запросов.

### For-comprehensions (углублённо)

#### Десахаризация в `map`, `flatMap`, `withFilter`
Конструкция `for`/`yield` — синтаксический сахар, который компилятор переводит в цепочки вызовов `map`, `flatMap` и `withFilter`.

Правила трансляции:
- `for (x <- expr) yield body` → `expr.map(x => body)`
- `for (x <- expr1; y <- expr2) yield body` → `expr1.flatMap(x => expr2.map(y => body))`
- `if`-охранник `if cond` → вызов `withFilter(cond)` перед последующей операцией.

Пример:
```scala
val result = for
  x <- List(1, 2, 3)
  y <- List('a', 'b')
  if x != 2
yield s"$x$y"
```
эквивалентно:
```scala
List(1,2,3)
  .withFilter(x => x != 2)
  .flatMap(x => List('a','b').map(y => s"$x$y"))
```

#### Использование с Option, Either, Future, списками
For-генераторы работают с любыми типами, которые определяют указанные методы с правильными сигнатурами (монадическими). Это позволяет писать последовательный код для работы с потенциально отсутствующими, ошибочными или асинхронными значениями.

**Option:**
```scala
val maybeAge: Option[Int] = Some(30)
val maybeName: Option[String] = Some("Alice")

val greeting = for
  name <- maybeName
  age  <- maybeAge
yield s"$name is $age years old"
// Some("Alice is 30 years old")
```

**Either** (или `IO`/`Future`):
```scala
def parseInt(s: String): Either[String, Int] =
  s.toIntOption.map(Right(_)).getOrElse(Left(s"Not an integer: $s"))

val sum = for
  a <- parseInt("10")
  b <- parseInt("20")
yield a + b
// Right(30)
```

`Future` (требует `ExecutionContext`):
```scala
import scala.concurrent.Future
import scala.concurrent.ExecutionContext.Implicits.global

val f1 = Future(10)
val f2 = Future(20)
val combined = for
  v1 <- f1
  v2 <- f2
yield v1 + v2
```

### Функциональная обработка ошибок

В функциональном программировании ошибки моделируются типами данных, а не исключениями. Это делает поток ошибок явным и типобезопасным.

#### `Option`: `Some`/`None`, операции `map`, `flatMap`, `getOrElse`, `orElse`
`Option[A]` представляет значение, которое может отсутствовать. `Some(a)` — наличие, `None` — отсутствие. Использование `Option` заменяет `null`.

```scala
def findUser(id: Int): Option[String] = if id == 1 then Some("Alice") else None

val userName = findUser(1).map(_.toUpperCase).getOrElse("Unknown")
```

- `map` применяет функцию к содержимому, сохраняя `None`.
- `flatMap` позволяет связывать операции, которые сами возвращают `Option`.
- `getOrElse` извлекает значение или возвращает значение по умолчанию.
- `orElse` предоставляет альтернативный `Option`.

#### `Either`: `Left`/`Right`, `map`, `flatMap`, `fold`
`Either[A, B]` описывает значение одного из двух типов. По соглашению `Left` используется для ошибки, `Right` — для успешного результата. Он право-смещённый (начиная с Scala 2.12), т.е. `map`, `flatMap` работают с `Right`.

```scala
def divide(a: Int, b: Int): Either[String, Int] =
  if b == 0 then Left("Деление на ноль")
  else Right(a / b)

val result = divide(10, 2).map(_ * 3)  // Right(15)
val failed = divide(10, 0).map(_ * 3)  // Left("Деление на ноль")
```

Метод `fold` принимает две функции: что делать с ошибкой и что — со значением:
```scala
val message = result.fold(
  err => s"Ошибка: $err",
  value => s"Результат: $value"
)
```

#### `Try`: `Success`/`Failure`, `recover`, `recoverWith`
`scala.util.Try[A]` оборачивает вычисление, которое может бросить исключение. `Success(v)` — успех, `Failure(ex)` — исключение.

```scala
import scala.util.Try

def parse(s: String): Try[Int] = Try(s.toInt)

val valid = parse("123").map(_ * 2)   // Success(246)
val invalid = parse("abc").map(_ * 2) // Failure(NumberFormatException)
```

- `recover` — принимает частичную функцию для обработки конкретных исключений и возвращает значение.
- `recoverWith` — аналогично, но возвращает `Try`, позволяя переключиться на альтернативное вычисление.

```scala
val recovered = invalid.recover {
  case _: NumberFormatException => 0
}  // Success(0)
```

#### Паттерн "железнодорожная колея" (railway oriented programming)
Это подход к построению цепочек обработки данных, где каждый шаг может завершиться успешно (`Success` / `Right`) или ошибкой (`Failure` / `Left`). Ошибки передаются по отдельному пути (рельсе), успешные значения — по другому. Комбинаторы `map`, `flatMap` позволяют связывать шаги, не проверяя явно наличие ошибки после каждого вызова.

```scala
def validateAge(age: Int): Either[String, Int] =
  if age < 0 then Left("Отрицательный возраст")
  else Right(age)

def checkAdult(age: Int): Either[String, Int] =
  if age >= 18 then Right(age)
  else Left("Несовершеннолетний")

def process(age: Int): Either[String, String] =
  for
    valid <- validateAge(age)
    adult <- checkAdult(valid)
  yield s"Возраст $adult принят"
```

Этот стиль делает обработку ошибок лаконичной и композируемой, избегая громоздких вложенных `if` или `try-catch`.
