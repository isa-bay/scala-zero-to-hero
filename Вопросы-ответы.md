- Какие типы литералов поддерживаются в Scala?  
  - целочисленные (`42`, `0x2A`)
  - с плавающей точкой (`3.14`, `1e-9`)
  - символьные (`'A'`)
  - строковые (`"text"`, многострочные `"""..."""`)
  - булевы (`true`, `false`)
  - кортежные (`(1, "a")`)
  - функциональные (лямбды `x => x+1`)
  - XML-литералы (`<tag>...</tag>` – устаревают)
  - а также литералы символов (`'symbol` – устарели)  

- Какие особенности работы со строками есть в Scala?  
   Строки неявно обогащаются через `StringOps`, добавляя методы `map`, `filter`, `reverse` и др.  
   Интерполяция: `s"$value"` (подстановка), `f"$value%2d"` (форматирование), `raw"..."` (без экранирования)  
   Многострочные строки через тройные кавычки  
   Сравнение по содержимому (а не по ссылке)  

- Перечислите виды идентификаторов:  
   - Альфа-цифровые: начинаются с буквы или `_`, затем буквы, цифры, `_`.  
   - Операторные: состоят из символов операций (например, `+`, `::`, `#::`).  
   - Смешанные: содержат и буквы, и операторные символы (разделяются подчёркиванием, например `unary_+`).  
   - В обратных кавычках: позволяют использовать зарезервированные слова или любые символы (например, ``` `yield` ```).  

4. В чём разница между `val`, `var` и `lazy val`?  
   - `val` – неизменяемая ссылка, вычисляется при инициализации (строго).  
   - `var` – изменяемая переменная.  
   - `lazy val` – неизменяемая, но вычисляется лениво (при первом обращении) и затем кэшируется.  

5. В чём основные синтаксические и парадигмальные отличия Scala от Java?  
   Scala – гибрид ООП и ФП, поддерживает функции высшего порядка, неизменяемость по умолчанию, вывод типов, pattern matching, трейты с миксинами, неявные параметры, монады, корутины (через эффекты). Синтаксис лаконичнее: нет `public static`, есть `object`, нет примитивов (всё объекты), операторы – методы, замыкания, for-comprehensions.  

6. Что такое `Unit` и `()` в Scala?  
   `Unit` – тип, означающий отсутствие полезного значения, аналог `void` в Java
   `()` – единственное значение типа `Unit`. Используется как возвращаемый тип для побочных эффектов

7.  В чём разница между `Nil`, `None`, `Nothing` и `Null`?  
   - `Nil` – пустой список (`List[Nothing]`), синглтон.  
   - `None` – отсутствие значения в `Option` (подтип `Option[Nothing]`).  
   - `Nothing` – нижний тип, подтип всех типов; используется как тип возврата для методов, бросающих исключения, или в пустых коллекциях.  
   - `Null` – тип, содержащий только `null`; подтип всех ссылочных типов (кроме `AnyVal`). В Scala `null` используется редко, предпочтительнее `Option`.  

8. Какова область видимости переменных в Scala?  
   Переменные видны в блоке, где объявлены, а также во вложенных блоках (затенение). Также есть область видимости пакета, класса, объекта, метода. Модификаторы доступа управляют видимостью.  

9. Какие модификаторы доступа существуют и как они работают?  
   - `private` – доступ только внутри класса/объекта.  
   - `protected` – доступ внутри класса и подклассов.  
   - `private[scope]` – доступ внутри указанного пакета, класса или объекта (visibility scope). По умолчанию – публичный (всеобщий).  

10. В чём разница между классом и объектом (`object`)?  
    Класс – шаблон для создания экземпляров. Объект – синглтон, создаётся единственный экземпляр автоматически, не может иметь параметров. Объект может содержать статические методы (в терминах Java) и используется для компаньонов, паттернов, утилит.  

11. Что такое сопутствующие объекты и их преимущества?  
    Компаньон – объект с тем же именем, что и класс, определённый в том же файле. Они имеют доступ к приватным членам друг друга. Преимущества: фабричные методы (`apply`), неявные области видимости (класс-компаньон – место для неявных экземпляров), организация статических методов, реализация экстракторов (`unapply`).  

12.  Что такое value classes и для чего они применяются?  
    Классы, наследующие `AnyVal`, с единственным полем. Компилятор избегает аллокации, заменяя экземпляр на значение поля во время выполнения (при определённых условиях). Используются для создания типобезопасных обёрток (например, `case class UserId(value: Long) extends AnyVal`) без накладных расходов на память.  

13. В чём отличие `trait` от абстрактного класса?  
    Трейт не имеет конструктора с параметрами (до Scala 3 – нет), поддерживает множественное наследование (миксины), не может передавать параметры (кроме зависимых типов). Абстрактный класс может иметь конструктор с параметрами, но поддерживает только одиночное наследование. Трейты предпочтительнее для композиции поведения; абстрактные классы – когда нужна иерархия с общим состоянием.  

14.  Что такое `sealed` трейты/классы и их роль в паттерн-матчинге?  
    `sealed` ограничивает наследование только внутри того же файла. Компилятор знает все возможные подтипы и может предупредить о неполноте pattern matching (проверка на исчерпываемость). Это основа для алгебраических типов данных (ADT).  

15. Что такое кейс-классы и какие методы они генерируют?  
    Классы с модификатором `case`. Автоматически генерируют: `equals`, `hashCode`, `toString`, `copy`, компаньон с `apply` и `unapply`, реализуют `Product` и `Serializable`. Поддерживают паттерн-матчинг. Используются для неизменяемых данных.  

16.  Как работают `equals` и `hashCode` в кейс-классах и влияние на коллекции?  
    `equals` сравнивает все поля структурно, `hashCode` строится на основе полей. Это обеспечивает корректное поведение в хеш-таблицах (`HashSet`, `HashMap`) при неизменяемости. При изменении поля (если класс не immutable) – ломается контракт, поэтому кейс-классы должны быть неизменяемыми.  

17. Что такое экстракторы и их роль?  
    Экстрактор – объект с методом `unapply` (или `unapplySeq`), который принимает объект и возвращает `Option` или `Some` с извлечёнными полями. Используется для деструктуризации в паттерн-матчинге, позволяя пользовательским классам участвовать в сопоставлении.  

18.  Различие между `apply` и `unapply`.  
    `apply` – фабричный метод, вызывается как `ClassName(...)` для создания экземпляра. `unapply` – обратное преобразование, извлекает поля для pattern matching. Вместе образуют механизм конструирования/деконструирования.  

19. Что такое вспомогательные конструкторы и правила их вызова?  
    Дополнительные конструкторы, объявленные как `def this(...)`. Первым действием они должны вызывать другой конструктор (`this`), что гарантирует делегирование цепочки к первичному конструктору.  

20. Что такое кортежи и их применение?  
    Неизменяемые гетерогенные последовательности фиксированного размера (от 1 до 22 в Scala 2, в Scala 3 без ограничений). Используются для группировки нескольких значений без создания отдельного класса, возврата нескольких значений из метода, распаковки в паттернах (`val (a, b) = tuple`).  

21. Определите `Set` и `BitSet` – особенности и производительность.  
    `Set` – коллекция уникальных элементов. Есть immutable и mutable версии. `BitSet` – реализация множества для целых неотрицательных чисел, хранящая битовые маски, очень компактна и быстра для операций над диапазонами, особенно в `immutable.BitSet` (представлена как `Array[Long]`).  

22.  Основные принципы работы коллекций Scala (mutable vs immutable, персистентность).  
    Immutable коллекции персистентны: операции модификации возвращают новую коллекцию, разделяя неизменяемую структуру для эффективности (структурное совместное использование). Mutable коллекции изменяются на месте. По умолчанию предпочтение отдаётся immutable из соображений безопасности и ФП.  

23.  Как работают `sortBy`/`sortWith` и стабильность сортировки.  
    `sortBy` принимает функцию извлечения ключа и сортирует по естественному порядку ключей. `sortWith` принимает функцию сравнения. Сортировка в Scala (через `java.util.Arrays.sort`) стабильна (сохраняет порядок равных элементов) для ссылочных типов.  

24. Какие циклы поддерживаются и преимущества `for`-выражений?  
    Циклы: `while`, `do-while` (императивные) и `for` (синтаксический сахар). `for`-выражения десугарятся в `flatMap`/`map`/`filter`, поддерживают генераторы, фильтры (`if`), определения переменных. Используются для работы с монадами (списки, опции, будущие значения), обеспечивая композицию без явного вложения вызовов.  

25. Что такое функции высшего порядка и их роль?  
    Функции, принимающие другие функции как параметры или возвращающие функции. Лежат в основе коллекций (`map`, `filter`, `fold`), позволяют абстрагировать императивные циклы, строить композицию, реализовать паттерны (декоратор, стратегия), способствуют модульности и переиспользованию.  

26. Разница между методом (`def`) и функцией (`FunctionN`)?  
    Метод (`def`) – член класса/объекта, не является значением, компилируется в виртуальный вызов. Функция – объект, наследующий `FunctionN`, может быть передана как значение. Преобразование метода в функцию (ETA-expansion) происходит при передаче `def` туда, где ожидается `FunctionN` (например, `list.map(_.toString)`).  

27. Что такое анонимные функции (лямбды)?  
    Безымянные функции, определяемые синтаксисом `(x: T) => expr` или с использованием заполнителей `_` (например, `_ + 1`). Компилируются в экземпляры `FunctionN`. Используются для краткой передачи поведения.  

28. Что такое частичные функции и отличие от полных?  
    Частичная функция (`PartialFunction[A, B]`) – функция, определённая не для всех значений домена. Имеет метод `isDefinedAt`. В паттерн-матчинге используется как серия `case`; может применяться с `collect` к коллекциям. Отличается от полной тем, что может быть не определена, что проверяется перед вызовом.  

29. Что такое монады в Scala? Назовите основные.  
    Монады – абстракция для композиции вычислений с контекстом. Имеют операции `map`, `flatMap`, `pure` (или `unit`). Основные: `Option` (возможное отсутствие), `Try` (исключения), `Either` (ошибки), `List` (недетерминизм), `Future` (асинхронность), `IO` (эффекты).  

30. Что такое `Option` и как использовать?  
    `Option` – контейнер, который может быть `Some(value)` или `None`. Используется вместо `null`. Основные методы: `map`, `flatMap`, `filter`, `getOrElse`, `orElse`, `fold`, паттерн-матчинг. Позволяет безопасно обрабатывать отсутствие значения.  

31. Что такое `Either`, `Left`, `Right` и обработка ошибок?  
    `Either` – тип с двумя альтернативами: `Left` (обычно ошибка) и `Right` (успех). В Scala 2.13+ `Either` правобокий (проекция). Используется для функциональной обработки ошибок без исключений: возврат `Left(error)` или `Right(value)`. Комбинируется через `map`/`flatMap` (работают с правой стороной).  

32.  Отличие `Try` от `Either` и когда применять.  
    `Try` – для синхронных вычислений, которые могут выбросить исключение; обёртывает результат или исключение (`Success`/`Failure`). `Either` – более гибкий, позволяет явно задать тип ошибки (не только `Throwable`), и используется и для синхронных, и для асинхронных сценариев. `Try` удобен, когда ошибки – только исключения, `Either` – когда ошибки – бизнес-значения.  

33. Разница между `flatMap` и `map` (пример).  
    `map` преобразует значение внутри контейнера, сохраняя структуру. `flatMap` применяет функцию, возвращающую контейнер, и «сплющивает» результат, предотвращая вложение. Пример: `Some(3).map(x => Some(x+1))` даст `Some(Some(4))`, тогда как `flatMap` даст `Some(4)`.  

34. Что такое for-comprehensions и их связь с монадами?  
    `for { x <- ma; y <- f(x) } yield y` десугарится в `ma.flatMap(x => f(x).map(y => y))` (с учётом фильтров). Это сахар для работы с монадами (опциями, списками, будущими). Позволяет писать цепочки вычислений в стиле плоских последовательностей.  

35. Что такое каррирование и его применение?  
    Преобразование функции от нескольких аргументов в цепочку функций от одного аргумента, например `def f(a: Int)(b: Int) = a+b`. Применение: частичное применение (фиксация части аргументов), внедрение зависимостей (особенно с неявными параметрами), улучшение композиции, использование в `implicit`-параметрах.  

36. Что такое ссылочная прозрачность и почему важна?  
    Выражение ссылочно прозрачно, если его можно заменить на его значение без изменения поведения программы. Это основа функционального программирования: упрощает тестирование, оптимизацию, доказательство корректности, позволяет ленивые вычисления и распараллеливание.  

37. Что такое классы типов и их реализация через неявные параметры?  
    Класс типов (type class) – паттерн, определяющий поведение для типов без изменения самих типов (адаптер). В Scala реализуется через трейт-тип-класс, неявные экземпляры для конкретных типов, и контекстные границы (`[T: Monoid]`), что позволяет компилятору подставлять неявные реализации.  

38. Что такое `Future` и обработка ошибок в ней?  
    `Future` – асинхронное вычисление, возвращающее результат позже. Ошибки обрабатываются через каналы: `recover` (восстановление), `recoverWith` (восстановление с возвратом Future), `onComplete` (колбэк), `transform` (преобразование успеха/ошибки), а также через `map`/`flatMap` (бросают исключения в случае ошибки, но их надо перехватывать через каналы).  

39. Чем отличаются конкурентность и параллелизм, какие конструкции их обеспечивают?  
    Конкурентность – логическое чередование задач (структура программы). Параллелизм – одновременное выполнение (железо). В Scala: для параллелизма – `Parallel Collections`, `par`; для конкурентности – `Future`, `Akka` (акторы), потокобезопасные структуры; для функционального конкурентного/параллельного программирования – `ZIO`, `Cats Effect` с их волокнами и пулами потоков.  

40. Как работает хвостовая рекурсия и влияние `@tailrec`?  
    Хвостовая рекурсия – когда рекурсивный вызов является последней операцией. Компилятор оптимизирует её в цикл, не увеличивая стек. Аннотация `@tailrec` заставляет компилятор выдавать ошибку, если оптимизация невозможна, гарантируя стекобезопасность.  

41.  Что делает `@tailrec`?  
    Проверяет, что метод является хвостовым рекурсивным; если нет – ошибка компиляции. Это гарантирует, что рекурсия будет оптимизирована в итерацию, предотвращая `StackOverflowError`.  

42. Разница между обычной и хвостовой рекурсией.  
    Обычная рекурсия сохраняет состояние каждого вызова в стеке, что ограничено размером стека. Хвостовая рекурсия не сохраняет состояние после вызова, компилятор заменяет её на цикл, потребляет O(1) стековой памяти.  

43. Что такое неявные параметры и преобразования?  
    Неявные параметры – параметры, помеченные `implicit`, которые компилятор заполняет из текущей области, если они не указаны явно. Неявные преобразования – методы/функции, помеченные `implicit`, автоматически применяемые для преобразования типов. Используются для расширения классов, внедрения зависимостей, классов типов. Следует применять осмотрительно из-за неявной сложности.  

44.  Что такое `implicit class`?  
    Класс, помеченный `implicit`, с конструктором, принимающим один параметр. Позволяет добавлять методы к существующим типам без наследования (расширение). Например, `implicit class RichString(s: String) { def toIntOption = ... }`.  

45. Что такое ленивые вычисления (`lazy val`, `Stream`/`LazyList`)?  
    Отложенное вычисление значения до первого использования (`lazy val`). `LazyList` (ранее `Stream`) – ленивая связанная последовательность, элементы вычисляются при необходимости. Применяются для работы с бесконечными данными, оптимизации производительности, избегания ненужных вычислений.  

46.  Что такое `view` или `LazyList`?  
    `view` (на коллекциях) создаёт ленивый обход, позволяя цепочку преобразований без промежуточных коллекций (например, `list.view.map(...).filter(...).toList`). `LazyList` – это ленивый список с мемоизацией ранее вычисленных элементов. Оба помогают уменьшить память и ускорить работу при пайплайнах.  

47. Что такое дисперсия (variance) в параметризованных типах?  
    Определяет отношение подтипов между параметризованными типами:  
    - Ковариантность (`+A`) – `C[A]` подтип `C[B]` если `A <: B`.  
    - Контравариантность (`-A`) – `C[A]` подтип `C[B]` если `A >: B`.  
    - Инвариантность – нет подтипов.  
    Используется для сохранения безопасности типов в коллекциях и функциях (например, `List[+A]`).  

48.  Что такое path-dependent types?  
    Типы, которые зависят от конкретного экземпляра внешнего объекта (пути). Например, внутри трейта `trait A { type T }`, тип `A#T` – общий, а `a.T` – зависит от экземпляра `a`. Используются для выражения связей между типами, например, в зависимых классах или при реализации типобезопасных API (как в ScalaCheck).  

49. Что такое монадические функции (`pure`, `map`, `flatMap`)?  
    `pure` (или `unit`) – помещает значение в минимальный контекст монады. `map` – применяет функцию к значению внутри контекста. `flatMap` – применяет функцию, возвращающую новый контекст, и «сплющивает» вложенность. Эти функции образуют монаду, обеспечивая композицию вычислений с эффектами.  

50. Разница между монадой и аппликативным функтором?  
    Аппликативный функтор – промежуточный слой между функтором и монадой: имеет `apply` (или `<*>`) для применения функций в контексте, но не может использовать результат предыдущего вычисления для выбора следующего вычисления (как `flatMap`). Монада – более мощная, позволяет последующие вычисления зависеть от предыдущих результатов (через `flatMap`).  

51. Система эффектов: сравните `IO` и `Future`.  
    `Future` – строгая, асинхронная, с побочными эффектами при создании (запускается сразу), не ссылочно прозрачна (кеширует результат). `IO` (из Cats Effect/ZIO) – ленивая, описывает программу как значение, позволяет контролировать запуск, обеспечивает ссылочную прозрачность, управляет ресурсами, поддерживает прерывание, лучше интегрируется с ФП.  

52. Что такое Akka и как используется?  
    Akka – фреймворк для построения конкурентных, распределённых и отказоустойчивых систем на основе модели акторов (Actor Model). Используется для создания микросервисов (Akka HTTP), кластеризации, управления состоянием, CQRS/Event Sourcing (Akka Persistence). Обеспечивает изоляцию, локацию прозрачность и супервизию.  

53. Как бы вы реализовали REST API на Scala с использованием Akka HTTP?  
    Определили маршруты (DSL `path`, `get`, `post`), внутри – директивы для обработки запросов, сериализация/десериализация JSON (например, через Circe), взаимодействие с бизнес-логикой (акторы или Future), обработка ошибок через `complete`/`recover`. Всё заворачивается в `Route` и запускается через `Http().bindAndHandle`.  

54. Что такое Tagless Final?  
    Стиль написания программ, параметризованных абстрактным эффектом `F[_]`, ограниченным классом типов (например, `Monad[F]`). Код не зависит от конкретного эффекта, интерпретация (IO, Future, Id) задаётся отдельно. Обеспечивает тестируемость, композицию, отделение описания от выполнения, легкость замены реализации.  

55. Как компилируется код Scala?  
    Исходный код → синтаксический анализ → построение AST → тайпчекинг (с учётом неявных преобразований, вывода типов) → генерация промежуточного представления (например, TASTy в Scala 3) → эрайзер (стирание дженериков для JVM) → генерация Java-байткода (.class). Дополнительные этапы: сид-фазы, десугаризация for, паттерн-матчинга, синтетических методов.  

56.  Как компилируется сопоставление с образцом?  
    Паттерн-матчинг десугаризируется в серию вызовов `unapply`/`unapplySeq`, ветвлений (if/else) и проверок типов, с оптимизациями для кейс-классов (используются их `unapply`). В некоторых случаях генерируется метод `$match` или используется `switch` для простых паттернов.  

57. Что такое «тип Кюри» (Curry-Howard isomorphism) в контексте Scala?  
    Соответствие между типами (как логическими формулами) и программами (как доказательствами). В Scala это проявляется в том, что типы-функции соответствуют импликации, кортежи – конъюнкции, `Either` – дизъюнкции, а `Nothing` – лжи. Используется для доказательства свойств программ через типы (например, в библиотеках для зависимых типов).  

58.  Назовите основные инструменты сборки для Scala, особенности sbt.  
    Основные: sbt (де-факто стандарт), Mill (более быстрый, функциональный), Maven (с плагином Scala). sbt использует собственный DSL на основе Scala, поддерживает инкрементальную компиляцию, параллельную сборку, плагины, режим «сна» (очень быстрые перезагрузки).  

59.  Особенности работы с immutable и mutable коллекциями – как выбирать?  
    По умолчанию использовать immutable (безопасность, ссылочная прозрачность, лёгкость тестирования). Mutable – только когда производительность критична (например, частые обновления больших данных) или при тесном взаимодействии с Java. Также можно использовать `mutable` локально внутри функции, не выставляя наружу.
