## Введение в Scala

### Что такое Scala? Мультипарадигменный язык (ООП + ФП)
Scala (Scalable Language) — это статически типизированный язык программирования, объединяющий объектно-ориентированную и функциональную парадигмы.  
- **ООП**: каждое значение является объектом, каждая операция — вызов метода. Есть классы, трейты, наследование, абстрактные члены.  
- **ФП**: функции — объекты первого класса, поддерживаются неизменяемые структуры данных, алгебраические типы, pattern matching, монадические конструкции (`Option`, `Either`, `Try`).  

Благодаря строгой статической типизации и мощному выводу типов код получается лаконичным и безопасным.

### История создания и развития (Scala 2, Scala 3)
- **2004** — Мартин Одерский (Martin Odersky) выпустил первую версию Scala, реализовав идеи языка Funnel и совместив ООП и ФП на JVM.  
- **2006** — Scala 2.0: переработанная система типов, неявные параметры (implicits).  
- **2016** — Scala 2.12: поддержка Java 8, лямбда-оптимизации.  
- **2019** — Scala 2.13: коллекции переписаны, улучшенный вывод типов.  
- **2021** — Scala 3 (Dotty): новый синтаксис (опциональные отступы, `given`/`using` вместо implicit, перечисления `enum`, объединённые и пересечённые типы, метапрограммирование).  

Scala 3 не ломает совместимость: проекты на Scala 2 и Scala 3 могут сосуществовать, доступен механизм `-Xsource:3` и автоматическая миграция.

### Философия: лаконичность, безопасность типов, масштабируемость
- **Лаконичность**: меньше шаблонного кода по сравнению с Java (case-классы, вывод типов, функции высшего порядка).  
- **Безопасность**: строгая статическая типизация исключает целые классы ошибок на этапе компиляции; `null` в обычном коде не используется — вместо него `Option`.  
- **Масштабируемость**: язык одинаково удобен для небольших скриптов и крупных распределённых систем; DSL-ориентированный синтаксис и возможность создавать библиотеки, выглядящие как встроенный синтаксис.

### Scala на JVM: компиляция в байт-код, совместимость с Java
- Исходный код `.scala` компилируется в байт-код JVM (`.class`-файлы) с помощью `scalac`.  
- Скомпилированный код полностью совместим с Java: можно вызывать Java-библиотеки, наследовать Java-классы, аннотировать Java-аннотациями.  
- Обратная совместимость: Java может вызывать Scala-код при соблюдении определённых правил (без использования «сложных» конструкций, типа каррирования).  

Пример вызова Java из Scala:
```scala
import java.time.LocalDate
val today = LocalDate.now()
```

### Scala.js и Scala Native — обзор платформ
- **Scala.js** — компилятор Scala в JavaScript. Позволяет писать фронтенд-приложения на Scala, взаимодействовать с DOM и JS-библиотеками.  
- **Scala Native** — компиляция в нативный код через LLVM, без JVM. Даёт быстрое время запуска и низкий расход памяти, но не все JVM-библиотеки доступны.  

### Области применения: бэкенд, большие данные, стриминг, распределённые системы
- **Бэкенд**: Play Framework, Akka HTTP, http4s, Tapir.  
- **Большие данные**: Apache Spark (основной язык API — Scala), Flink.  
- **Стриминг**: Akka Streams, Kafka Streams (через Scala-обёртки).  
- **Распределённые системы**: Akka (Actor Model), Pekko (форк Akka).  
- **Функциональное программирование**: экосистема Typelevel (Cats, Cats Effect, FS2, Doobie, http4s) и ZIO.


## Установка и настройка

### Установка JDK (версии, совместимость)
Scala требует JDK 8 или выше. Для Scala 2.12/2.13 рекомендуются JDK 8/11/17, Scala 3 — JDK 11/17/21.  
Проверка установки:
```bash
java -version
javac -version
```
Скачать JDK можно с [Adoptium](https://adoptium.net/) или `sdkman`.

### Установка Scala: sdkman!, coursier, системные пакеты
**Рекомендуемый способ — `sdkman`** (Linux, macOS, WSL):
```bash
sdk install scala 3.4.2   # или sdk install scala 2.13.14
```
**Coursier** — универсальный установщик:
```bash
curl -fL https://github.com/coursier/coursier/releases/latest/download/cs-x86_64-pc-linux.gz | gzip -d > cs && chmod +x cs && ./cs setup
```
После установки Coursier добавляет в PATH `scala`, `scalac`, `sbt`, `cs`.  

**Системные пакеты** (Linux):  
```bash
# Ubuntu
sudo apt install scala
# macOS (Homebrew)
brew install scala
```
*Однако версии из репозиториев могут устаревать, поэтому sdkman/coursier предпочтительнее.*

### Первая программа "Hello, World!" (компиляция и запуск)
Создайте файл `Hello.scala`:
```scala
@main def hello = println("Hello, World!")
```
Скомпилируйте и запустите:
```bash
scalac Hello.scala
scala hello
```
Или одной командой через `scala` (без компиляции вручную):
```bash
scala Hello.scala
```
Ещё проще — **Scala CLI** (см. ниже).

### REPL и рабочие листы (Ammonite, IntelliJ Scala Worksheet)
- **REPL** (Read-Eval-Print Loop) запускается командой `scala` без аргументов:
  ```scala
  scala> val x = 42
  scala> println(x)
  ```
- **Ammonite** — улучшенный REPL с автодополнением, многострочными вставками, поддержкой зависимостей:
  ```bash
  amm
  @ val list = List(1,2,3)
  @ list.map(_ * 2)
  ```
  Установка через `sdk install ammonite` или `coursier install ammonite`.
- **Scala Worksheet** — файл `.sc` в IntelliJ IDEA, где можно интерактивно выполнять код и видеть результаты справа.

### Scala CLI для быстрых экспериментов
`scala-cli` — современный инструмент для запуска, компиляции, упаковки Scala-кода без сложной настройки.
Установка:
```bash
brew install Virtuslab/scala-cli/scala-cli   # macOS
sdk install scalacli                         # sdkman
curl -sSLf https://scala-cli.virtuslab.org/get | sh   # Linux/macOS
```
Использование:
```bash
scala-cli run .
scala-cli compile Hello.scala
scala-cli package Hello.scala --js  # компиляция в Scala.js
```
Можно встраивать зависимости прямо в файл:
```scala
//> using dep "org.typelevel::cats-core:2.10.0"
import cats.syntax.all.*
println(1.valid)
```

## Инструменты разработки

### Выбор IDE: IntelliJ IDEA + Scala plugin, Metals (VS Code, Vim)
- **IntelliJ IDEA** (Community/Ultimate) + официальный Scala-плагин: мощный редактор с инспекциями, автодополнением, поддержкой sbt.  
- **Metals** — LSP-сервер для Scala, работает с VS Code, Vim (coc-metals), Emacs. Предоставляет автодополнение, навигацию, диагностику. Устанавливается через Coursier.
- **Sublime Text / Atom** — есть неофициальные пакеты, но Metals предпочтительнее.

### Обзор проекта: структура каталогов, исходники, ресурсы
Типичная sbt-структура проекта:
```
my-project/
├── build.sbt
├── project/
│   └── build.properties
├── src/
│   ├── main/
│   │   ├── scala/          # исходники приложения
│   │   │   └── Main.scala
│   │   └── resources/      # конфигурационные файлы и ресурсы
│   └── test/
│       ├── scala/          # тесты
│       └── resources/
└── target/                 # скомпилированные классы, артефакты (генерируется)
```
Пример `build.sbt`:
```scala
scalaVersion := "3.4.2"
name := "my-project"
version := "0.1.0"
```

### Работа в терминале: scalac, scala, sbt
- `scalac` — компилятор. Создаёт `.class`-файлы.  
  ```bash
  scalac -d out Hello.scala
  scala -cp out hello
  ```
- `scala` — запускает Scala-класс или скрипт.  
- `sbt` (Scala Build Tool) — стандартный инструмент сборки и управления зависимостями.  
  ```bash
  sbt run            # компиляция и запуск Main-класса
  sbt console        # запуск REPL с classpath проекта
  sbt test           # запуск тестов
  sbt package        # создание JAR
  ```

### Частые проблемы и их решение
- **Ошибка «java: command not found»** — не установлен JDK или PATH не настроен.  
- **Несовместимость версий Scala и библиотек** — в Scala минорные версии не бинарно совместимы; библиотеки публикуются с суффиксом `_2.13` / `_3`. Используйте правильную версию в `build.sbt`.  
- **OutOfMemoryError при компиляции** — увеличить память JVM для sbt (`sbt -mem 4096`).  
- **Медленная IDE** — попробовать Metals или увеличить heap для IntelliJ.  
- **NullPointerException** — в Scala используйте `Option` вместо `null`, избегайте неинициализированных `var`.

## Основные концепции

### Компиляция и интерпретация
Scala код компилируется в байт-код JVM, но можно запускать и скрипты `.scala` через `scala`, которые компилируются на лету.  
Чистой интерпретации нет, однако REPL создаёт временные сессии с компиляцией в памяти.

### Байт-код и JVM
Байт-код — промежуточное представление, исполняемое виртуальной машиной Java (JVM). JVM обеспечивает переносимость, сборку мусора, JIT-компиляцию в машинный код во время выполнения.  
Имена Scala-классов могут содержать символы, допустимые в JVM (в т.ч. `$`), но внутреннее представление маппится на Java-имена. Например, `object Hello` создаёт класс `Hello$`.

### Сравнение Scala и Java (основные отличия)

| Характеристика        | Scala                                      | Java                         |
|-----------------------|--------------------------------------------|------------------------------|
| Вывод типов          | Широкий вывод типов, редко нужно указывать | Ограниченный (только `var` с Java 10) |
| Функции              | Функции — объекты, можно передавать куда угодно | Только SAM-интерфейсы и лямбды |
| Case-классы          | Одноимённые классы с автоматическими методами `equals`, `hashCode`, `copy`, паттерн-матчинг | Требуют ручного определения (records в Java 14+) |
| Неизменяемость       | Культура иммутабельности, `val` по умолчанию | Склонность к изменяемым переменным |
| Коллекции            | Единая иерархия `Seq`, `Set`, `Map` с богатыми операциями | Интерфейсы и утилитные классы |
| Null-безопасность    | `Option[A]` вместо `null`                  | Появление `Optional` (Java 8) и `@Nullable` |
| Многопоточность      | Akka/Pekko, Cats Effect, ZIO, Future       | Потоки, CompletableFuture, Virtual Threads (Java 21) |
| DSL                  | Возможность создавать выразительные DSL    | Многословный синтаксис        |

Пример синтаксического отличия:
```scala
// Scala
val doubled = List(1,2,3).map(_ * 2)
```
```java
// Java
var doubled = List.of(1,2,3).stream().map(x -> x * 2).collect(Collectors.toList());
```

### Плюсы и минусы Scala

**Плюсы:**
- Сочетание ООП и ФП в одном языке.
- Лаконичный синтаксис, снижающий объём кода.
- Строгая статическая типизация с мощным выводом.
- Совместимость с JVM-экосистемой.
- Хорошая поддержка конкурентного и асинхронного программирования.
- Развитая экосистема библиотек для функционального программирования (Typelevel, ZIO).

**Минусы:**
- Более высокий порог входа из-за обилия концепций.
- Медленная компиляция по сравнению с Java (особенно в Scala 2; в Scala 3 заметно улучшена).
- Меньше библиотек, ориентированных только на Scala, но большинство Java-библиотек работают.
- Двоичная несовместимость между минорными версиями (2.12 ↔ 2.13) требует пересборки.
- Сообщество расколото на Scala 2 и Scala 3, хотя миграция активно идёт.
- Сложность метапрограммирования в Scala 2 (implicits/macros) упрощена в Scala 3, но всё ещё может запутывать.
