### Обзор библиотеки коллекций

Scala обладает богатой и продуманной библиотекой коллекций, построенной на единой иерархии трейтов. Это позволяет один раз выучить операции и применять их к самым разным структурам данных.

#### `scala.collection` — базовые трейты
Все коллекции наследуются от трейтов, расположенных в пакете `scala.collection`. Основные из них:
- `IterableOnce` — минимальная абстракция, позволяющая пройти по элементам один раз.
- `Iterable` — расширяет `IterableOnce`, предоставляя итератор и множество стандартных операций.
- `Seq`, `Set`, `Map` — три основные ветви коллекций: упорядоченные последовательности, множества и ассоциативные массивы.

Каждая ветвь представлена в двух вариантах: неизменяемые (`scala.collection.immutable`) и изменяемые (`scala.collection.mutable`).

#### Неизменяемые (`immutable`) и изменяемые (`mutable`) коллекции
- **Неизменяемые** коллекции после создания не меняют своё содержимое. Операции (добавление, удаление, фильтрация) возвращают новую коллекцию. Они потокобезопасны и предпочтительны в функциональном стиле.
- **Изменяемые** коллекции позволяют модифицировать данные на месте.

Пример:
```scala
val immList = List(1, 2, 3)
val newList = 0 :: immList   // List(0, 1, 2, 3), immList не изменился

val mutList = scala.collection.mutable.ListBuffer(1, 2, 3)
mutList += 4                 // исходный список изменён
```

#### Рекомендация: по умолчанию неизменяемые
Стандартный импорт в Scala автоматически делает доступными неизменяемые коллекции (их Predef-псевдонимы: `List`, `Vector`, `Set`, `Map`). Изменяемые коллекции нужно импортировать явно. Такой подход поощряет написание безопасного, функционального кода.

### Основные неизменяемые коллекции

#### `List` — односвязный список
`List` представляет собой цепочку узлов, где каждый узел содержит значение и ссылку на следующий элемент. Голова (head) доступна за O(1), хвост (tail) — за O(1), добавление в начало (`::`) — O(1). Произвольный доступ по индексу — O(n).

```scala
val list = 1 :: 2 :: 3 :: Nil   // List(1, 2, 3)
val head = list.head            // 1
val tail = list.tail            // List(2, 3)
val prepended = 0 :: list       // List(0, 1, 2, 3)
```

Используется, когда важны последовательные обходы, рекурсивные алгоритмы, стеки.

#### `Vector` — эффективный произвольный доступ
`Vector` — это плоское дерево с высоким коэффициентом ветвления, обеспечивающее эффективный доступ по индексу (логарифмическое время с малой константой), а также добавление/удаление с обоих концов за эффективное время.

```scala
val vec = Vector(1, 2, 3)
val third = vec(2)           // 3
val updated = vec.updated(1, 42)  // Vector(1, 42, 3)
```

`Vector` — стандартный выбор для индексированных последовательностей в функциональном стиле.

#### `Set`, `Map`
- **Set** — множество уникальных элементов. Порядок не гарантирован (в `immutable.Set` на основе хэша).
  ```scala
  val set = Set(1, 2, 3, 2)  // Set(1, 2, 3)
  set.contains(2)             // true
  set + 4                     // Set(1, 2, 3, 4)
  ```
- **Map** — отображение ключ-значение. Неизменяемая версия также основана на хэш-таблице.
  ```scala
  val map = Map("a" -> 1, "b" -> 2)
  val value = map("a")              // 1
  val safe = map.get("c")           // None
  val updated = map + ("c" -> 3)    // Map(a -> 1, b -> 2, c -> 3)
  ```

Также есть `SortedSet` и `SortedMap`, реализованные на основе деревьев и сохраняющие порядок ключей.

#### `Range`, `LazyList` (ленивый список)
- **Range** — последовательность равномерно распределённых целых чисел. Обычно создаётся через `to`, `until`, `by`.
  ```scala
  val r1 = 1 to 5         // Range(1,2,3,4,5)
  val r2 = 1 until 5      // Range(1,2,3,4)
  val r3 = 0 to 10 by 2   // Range(0,2,4,6,8,10)
  ```
  Range вычисляется лениво, хранит только начало, конец и шаг.
- **LazyList** (ранее `Stream` в Scala 2) — потенциально бесконечная последовательность, элементы которой вычисляются по требованию.
  ```scala
  val naturals: LazyList[Int] = LazyList.from(1)
  val firstFive = naturals.take(5).toList  // List(1, 2, 3, 4, 5)
  
  val fibs: LazyList[BigInt] = BigInt(0) #:: BigInt(1) #:: fibs.zip(fibs.tail).map(_ + _)
  ```

#### `Queue`, `Stack`
Неизменяемые `Queue` (FIFO) и `Stack` (LIFO) доступны в пакете `scala.collection.immutable`. Они реализованы через эффективные неизменяемые структуры (например, две половинки списка для очереди).

```scala
val queue = scala.collection.immutable.Queue(1, 2, 3)
val (element, newQueue) = queue.dequeue   // (1, Queue(2, 3))
val enqueued = queue.enqueue(4)           // Queue(1, 2, 3, 4)
```

### Основные изменяемые коллекции

#### `ArrayBuffer`, `ListBuffer`
- **ArrayBuffer** — изменяемый аналог `Vector`, поддерживающий быстрое добавление в конец и произвольный доступ.
  ```scala
  val buf = scala.collection.mutable.ArrayBuffer(1, 2, 3)
  buf += 4
  buf(0) = 10
  ```
- **ListBuffer** — изменяемый односвязный список, эффективный для построения списка итеративным добавлением, затем преобразуется в неизменяемый `List`.
  ```scala
  val lb = scala.collection.mutable.ListBuffer[Int]()
  lb += 1; lb += 2
  val lst = lb.toList   // List(1, 2)
  ```

#### `mutable.Map`, `mutable.Set`
Изменяемые версии позволяют добавлять, удалять и обновлять записи на месте.

```scala
val mutMap = scala.collection.mutable.Map("x" -> 10)
mutMap("y") = 20
mutMap += ("z" -> 30)
mutMap.remove("x")
```

Аналогично для `mutable.Set`.

#### `Array` (JVM-массив)
`Array` — это обёртка над нативными массивами JVM. Фиксированный размер, изменяемые элементы. Поддерживает generic-параметризацию, но компилятор требует `ClassTag` для создания.

```scala
val arr = Array(1, 2, 3)
arr(0) = 42
arr.length   // 3
```

Array обеспечивает высокую производительность и совместимость с Java, но в Scala-коде предпочтение отдают `Vector` или `ArrayBuffer`.

### Операции над коллекциями

#### Трансформации
- **`map`** — применяет функцию к каждому элементу.
- **`flatMap`** — применяет функцию, возвращающую коллекцию, и выравнивает результат.
- **`filter`** — оставляет элементы, удовлетворяющие предикату.
- **`collect`** — применяет частичную функцию, отбирая подходящие элементы и преобразуя их (комбинация фильтра и map).
  ```scala
  val numbers = List(1, 2, "три", 4.0)
  val doubled = numbers.collect { case i: Int => i * 2 }  // List(2, 4)
  ```
- **`flatten`** — преобразует коллекцию коллекций в плоскую коллекцию.
  ```scala
  List(List(1,2), List(3)).flatten  // List(1,2,3)
  ```

#### Свёртки
- **`foldLeft(z)(op)`** — левая свёртка с начальным значением `z`.
- **`foldRight(z)(op)`** — правая свёртка.
- **`reduce(op)`** — свёртка без начального значения, бросает исключение на пустой коллекции.
- **`scanLeft(z)(op)`** / **`scanRight`** — свёртка с коллекцией промежуточных результатов.

```scala
List(1,2,3).foldLeft(0)(_ + _)    // 6
List(1,2,3).scanLeft(0)(_ + _)    // List(0, 1, 3, 6)
```

#### Группировка и сортировка
- **`groupBy(f)`** — группирует элементы по ключу, полученному функцией.
  ```scala
  val words = List("cat", "dog", "apple", "bat")
  val byFirstChar = words.groupBy(_.head)  // Map('c' -> List(cat), 'd' -> List(dog), 'a' -> List(apple), 'b' -> List(bat))
  ```
- **`sortBy(f)`** — сортирует по вычисленному ключу.
- **`sortWith(lt)`** — сортирует с пользовательской функцией сравнения.
- **`partition(p)`** — разделяет на две коллекции: удовлетворяющие предикату и нет.
- **`span(p)`** — разделяет на начальный префикс, удовлетворяющий предикату, и остаток.

#### Агрегация
- **`sum`** — сумма элементов (для числовых типов).
- **`min`** / **`max`** — минимальное/максимальное значение.
- **`mkString(sep)`** — склеивает элементы в строку, вставляя разделитель.

```scala
List(1,2,3).mkString("[", ", ", "]")  // "[1, 2, 3]"
```

#### Доступ
- `head`, `tail`, `last`, `init` (все элементы кроме последнего).
- `take(n)`, `drop(n)`, `slice(from, until)`.

#### Объединение
- `++` — конкатенация двух коллекций.
- `:::` — конкатенация только для `List` (более идиоматично).
- `zip` — образует коллекцию пар из двух коллекций; `zipWithIndex` — пары элемент-индекс.

```scala
List(1,2).zip(List('a','b'))  // List((1,'a'), (2,'b'))
"scala".zipWithIndex           // Vector(('s',0), ('c',1), ...)
```

### Специальные типы данных

#### `Option` — детально
`Option[A]` — контейнер, который может либо содержать значение `Some(a)`, либо быть пустым `None`. Используется вместо `null`.

Ключевые операции:
- `map(f)` — применяет функцию к содержимому, сохраняя `None`.
- `flatMap(f)` — применяет функцию, возвращающую `Option`, позволяет выстраивать цепочки.
- `filter(p)` — превращает в `None`, если значение не удовлетворяет предикату.
- `getOrElse(default)` — извлекает значение или возвращает аргумент по умолчанию.
- `orElse(alternative)` — возвращает этот `Option`, если он непуст, иначе альтернативный.
- `fold(default)(f)` — применяет `f` к значению или возвращает `default`, если `None`.
- `isDefined`, `isEmpty` — проверки наличия значения (старайтесь избегать и использовать map/flatMap).

```scala
val maybeName: Option[String] = Some("Alice")
val result = maybeName
  .filter(_.length > 3)
  .map(_.toUpperCase)
  .getOrElse("Unknown")
```

#### `Either` — обработка ошибок
`Either[A, B]` содержит либо значение типа `A` (обычно ошибка, `Left`), либо `B` (успех, `Right`). Начиная с Scala 2.12, `Either` право-смещённый, что позволяет использовать `map`, `flatMap`, for-comprehensions.

- `map(f)` — применяет к `Right`, оставляет `Left` без изменений.
- `flatMap(f)` — связывает операции, возвращающие `Either`.
- `left.map` (или `leftMap` в Scala 3/Cats) — преобразует левое значение.
- `fold(leftF, rightF)` — обрабатывает оба случая и выдаёт финальное значение одного типа.
- `swap` — меняет `Left` и `Right` местами.

```scala
def divide(a: Int, b: Int): Either[String, Int] =
  if b == 0 then Left("Division by zero")
  else Right(a / b)

val r = divide(10, 2).map(_ * 2).fold(identity, _.toString)  // "10"
```

#### `Try` — безопасное выполнение кода с исключениями
`scala.util.Try[A]` ловит нефатальные исключения и оборачивает результат в `Success[A]` или `Failure[Throwable]`.

```scala
import scala.util.Try

val attempt = Try("123".toInt)
attempt.map(_ + 1).getOrElse(0)   // 124

val failed = Try("abc".toInt)
failed.recover { case _: NumberFormatException => 0 }  // Success(0)
```

`Try` удобен для обёртывания Java-кода и взаимодействия с нечистыми функциями.

### For-comprehensions

Уже обсуждались в предыдущих разделах, но подчеркнём их роль с коллекциями: они позволяют писать почти императивный код, который транслируется в цепочки `flatMap`, `map`, `withFilter`. Работают с любыми типами, имеющими эти методы (монадическими).

```scala
val numbers = List(1, 2, 3)
val letters = List('a', 'b')
val pairs = for
  n <- numbers
  l <- letters
  if n != 2
yield s"$n$l"
// List("1a", "1b", "3a", "3b")
```

С `Option` и `Either` получается лаконичная обработка возможных ошибок без вложенных проверок.

### Представления (views) и итераторы

#### Ленивые вычисления: `view`
Вызов `.view` на коллекции создаёт ленивое представление, которое применяет трансформации «на лету», не строя промежуточных коллекций. Это позволяет избежать лишних проходов при цепочках операций.

```scala
val res = (1 to 10_000_000).view
  .map(_ * 2)
  .filter(_ % 3 == 0)
  .take(5)
  .toList
```

Без `.view` каждая операция создавала бы новую коллекцию. С `.view` все трансформации вычисляются только для первых 5 элементов, прошедших фильтр.

#### Итераторы: `iterator`, потребление
Итератор (`Iterator`) — однократно потребляемая последовательность. Он полезен, когда нужно пройти по данным один раз и не хранить их в памяти.

```scala
val it = Iterator.continually(scala.util.Random.nextInt).take(5)
it.foreach(println)   // после этого итератор исчерпан
```

Итераторы не коллекции, они не поддерживают повторный обход, но имеют богатый набор методов (map, filter, ...).

### Интеграция с Java коллекциями

Для взаимодействия с Java-библиотеками Scala предоставляет `CollectionConverters` (до Scala 2.13 — `JavaConverters`).

```scala
import scala.jdk.CollectionConverters.*

val javaList: java.util.List[Int] = List(1, 2, 3).asJava
val scalaSeq: Seq[Int] = javaList.asScala.toSeq
```

Можно преобразовывать Map, Set и т.д. Обратите внимание: преобразования создают обёртки, а не копии (за исключением `.toSeq`, которое делает копию в неизменяемую коллекцию).

### Производительность коллекций

При выборе структуры данных учитывайте асимптотическую сложность основных операций.

| Операция          | List   | Vector  | Set (immutable) | Map (immutable) |
|-------------------|--------|---------|-----------------|-----------------|
| доступ по индексу | O(n)   | O(log n) | —               | —               |
| head             | O(1)   | O(1)*  | —               | —               |
| tail             | O(1)   | O(log n) | —               | —               |
| вставка в начало | O(1)   | O(log n) | —               | —               |
| вставка в конец  | O(n)   | O(log n) | —               | —               |
| поиск по значению | O(n)  | O(n)    | O(1)**           | O(1)** (по ключу) |
| добавление элемента | O(n) | O(log n) | O(1)**          | O(1)**          |

*Эффективно, но константа чуть выше из-за структуры дерева.  
**Эффективное время для хэш-реализаций (при отсутствии коллизий). Для SortedSet/SortedMap — O(log n).

- Используйте `List` для рекурсивных обходов, стековых операций, когда не нужен произвольный доступ.
- Используйте `Vector` для индексированных последовательностей общего назначения, когда нужен быстрый доступ и обновление.
- Для модификации больших последовательностей предпочитайте `ArrayBuffer` (изменяемый) или `Vector` (неизменяемый).
- При работе с множествами/картами с большим числом ключей и не требуется порядок — неизменяемые `HashSet`/`HashMap`.
- Если нужен порядок — `TreeSet`/`TreeMap` (сравнение) или `ListSet`/`ListMap` (сохранение порядка вставки, медленнее).

Помните, что неизменяемые коллекции создают новые версии структур, но используют структурное разделение (structural sharing), чтобы минимизировать копирование. Это даёт хороший баланс между производительностью и безопасностью
