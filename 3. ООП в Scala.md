### Классы и объекты

#### Определение класса: поля, методы
Класс объявляется ключевым словом `class`, за которым следует имя, список параметров конструктора и тело. Параметры конструктора могут автоматически становиться публичными полями, если перед ними стоит `val` или `var`. Иначе они доступны только внутри класса.

```scala
class Person(val name: String, var age: Int):
  def greet: String = s"Привет, меня зовут $name, мне $age лет."
  
val p = Person("Alice", 30)
println(p.name)  // Alice
p.age = 31       // можно изменять, т.к. var
```

В теле класса можно определять другие поля и методы. Обратите внимание: в Scala 3 используется синтаксис со значимыми отступами (как в примере), но можно по-прежнему ставить фигурные скобки.

#### Основной конструктор и вспомогательные конструкторы
Основной конструктор – это сам список параметров после имени класса. Тело класса выполняется при создании экземпляра. Дополнительные конструкторы задаются через `def this(...)` и должны вызывать основной или другой вспомогательный конструктор.

```scala
class Point(val x: Int, val y: Int):
  def this(coord: Int) = this(coord, coord) // вспомогательный конструктор

val p1 = Point(10, 20)
val p2 = Point(5) // x = 5, y = 5
```

Использование вспомогательных конструкторов в Scala обычно не приветствуется: чаще применяют фабричные методы в объекте-компаньоне или значения по умолчанию.

#### Синглтон-объекты (`object`)
`object` определяет класс и его единственный экземпляр (синглтон) одновременно. Объекты инициализируются лениво при первом доступе. У них нет параметров конструктора, они не могут быть инстанцированы через `new`.

```scala
object Logger:
  def log(msg: String): Unit = println(s"[INFO] $msg")

Logger.log("Запуск приложения")
```

Объекты могут расширять классы и трейты.

#### Companion object (объект-компаньон) — фабрики, неявные преобразования, статические члены
Когда в одном файле объявлены класс и объект с тем же именем, они называются компаньонами и имеют доступ к приватным членам друг друга. Объект-компаньон заменяет статические члены Java. В нём размещают фабричные методы (часто `apply`), неявные значения, константы.

```scala
class User private(val name: String, val id: Int)
object User:
  private var nextId = 0
  def apply(name: String): User =
    nextId += 1
    new User(name, nextId)

val u = User("Bob")   // вызов User.apply
```

Объект-компаньон также используется для размещения `given` (неявных значений) в Scala 3.

#### `apply` и `unapply` методы
- **`apply`** — метод, который можно вызывать как `Объект(аргументы)`. Часто используется как фабричный метод.
- **`unapply`** (экстрактор) — метод, позволяющий использовать объект в паттерн-матчинге. Возвращает `Option` (или `Boolean`).

```scala
class Email(val user: String, val domain: String)
object Email:
  def apply(address: String): Email =
    val parts = address.split("@")
    new Email(parts(0), parts(1))
  
  def unapply(email: Email): Option[(String, String)] =
    Some((email.user, email.domain))

val email = Email("john@example.com")
email match
  case Email(u, d) => println(s"Пользователь $u, домен $d")
```

Экстракторы могут определяться для любых классов, не только case-классов.

### Case-классы

#### Создание, неизменяемые поля
Case-классы объявляются с модификатором `case class`. Их параметры по умолчанию являются публичными `val`, добавлять `val` явно не обязательно. Они создаются без `new` (благодаря сгенерированному `apply` в компаньоне).

```scala
case class Point(x: Int, y: Int)

val p = Point(3, 4)
println(p.x) // 3
// p.x = 5   // ошибка компиляции: x — val
```

Case-классы удобны для моделирования данных, передачи сообщений в акторах, описания алгебраических типов данных.

#### Автоматически сгенерированные методы: `equals`, `hashCode`, `toString`, `copy`
- **`equals` и `hashCode`** — структурное сравнение по значениям полей.
- **`toString`** — человекочитаемое представление: `Point(3,4)`.
- **`copy`** — создание копии с возможностью изменения отдельных полей (на самом деле создаётся новый экземпляр).

```scala
val p1 = Point(1, 2)
val p2 = Point(1, 2)
p1 == p2          // true (структурное сравнение)

val p3 = p1.copy(y = 5)   // Point(1,5)
```

#### Pattern matching с case-классами
Компаньон case-класса содержит автоматически сгенерированный `unapply`, что позволяет извлекать поля в сопоставлении с образцом.

```scala
def describe(point: Point): String = point match
  case Point(0, 0) => "начало координат"
  case Point(x, 0) => s"на оси X в точке $x"
  case Point(0, y) => s"на оси Y в точке $y"
  case Point(x, y) => s"точка ($x, $y)"
```

### Наследование и композиция

#### Расширение классов: `extends`
Класс может расширять ровно один суперкласс с помощью `extends`. Абстрактные классы также могут быть унаследованы. Для подмешивания трейтов используется `with`.

```scala
class Animal(name: String):
  def speak: String = "..."

class Dog(name: String) extends Animal(name):
  override def speak: String = "Гав!"
```

Если суперкласс имеет параметры, подкласс обязан передать их в основной конструктор.

#### Переопределение методов и полей (`override`)
При переопределении конкретных (неабстрактных) членов обязательно ключевое слово `override`. При реализации абстрактных членов оно опционально, но его присутствие считается хорошим тоном.

```scala
abstract class Shape:
  def area: Double

class Circle(radius: Double) extends Shape:
  override def area: Double = Math.PI * radius * radius
```

Можно переопределять `val` (без `var`) неизменяемые поля, делая их более конкретными или вычисляемыми.

#### Абстрактные классы и абстрактные члены
Абстрактный класс объявляется с `abstract class`. Он может содержать как абстрактные, так и конкретные методы и поля. Нельзя создать экземпляр абстрактного класса напрямую.

```scala
abstract class DatabaseConnector:
  def connect(url: String): Unit
  def close(): Unit = println("Закрыт по умолчанию")
```

#### Запечатанные классы (`sealed`) для ограниченной иерархии
Модификатор `sealed` перед классом или трейтом ограничивает наследование: все прямые наследники должны быть объявлены в том же файле. Это позволяет компилятору выполнять исчерпывающую проверку в паттерн-матчинге.

```scala
sealed trait Result
case class Success(data: String) extends Result
case class Failure(error: String) extends Result

def handle(r: Result): String = r match
  case Success(d) => s"OK: $d"
  case Failure(e) => s"Error: $e"
// без sealed компилятор предложил бы добавить случай по умолчанию
```

`sealed` широко используется в алгебраических типах данных (ADT).

#### `final` классы и методы
- `final class` запрещает наследование от класса.
- `final` метод нельзя переопределить в подклассе.

```scala
final class Config private (val dbUrl: String)
class Base:
  final def importantLogic = 42
```

Использование `final` помогает компилятору оптимизировать вызовы и делает программу более безопасной.

### Traits (трейты)

#### Определение trait
`trait` — аналог интерфейса в Java, но с возможностью иметь реализацию методов, поля и состояние. Трейт нельзя инстанцировать напрямую, он подмешивается к классам.

```scala
trait Logger:
  def log(msg: String): Unit = println(s"LOG: $msg")
```

В Scala 3 трейты могут иметь параметры (как классы):
```scala
trait Named(val name: String):
  def greeting = s"Hello, $name"
```

#### Миксины: `with`, множественное наследование от trait'ов
Класс может расширять несколько трейтов с помощью `with`:
```scala
class Service extends Base with Logger with Auth
```
Если трейтов несколько, они упорядочиваются справа налево (линеаризация).

#### Линеаризация и разрешение ромбовидного наследования
Scala решает проблему множественного наследования с помощью линейной супертипизации. Для каждого класса выстраивается линейная последовательность супертипов. При вызове метода используется самая правая реализация в цепочке.

Пример ромбовидного наследования:
```scala
trait A:
  def msg = "A"
trait B extends A:
  override def msg = "B"
trait C extends A:
  override def msg = "C"
class D extends B with C

println(D().msg) // "C" (C правее B)
```
Порядок линеаризации: `D -> C -> B -> A -> AnyRef -> Any`. Правило «последний переопределяет» обеспечивает предсказуемое поведение.

#### Абстрактные и конкретные методы в trait'ах
Трейт может содержать как полностью реализованные, так и абстрактные методы. Класс, подмешивающий трейт, должен реализовать все абстрактные члены, если они ещё не реализованы в другом подмешанном трейте.

```scala
trait Iterator[A]:
  def hasNext: Boolean
  def next(): A
  def foreach(f: A => Unit): Unit =
    while hasNext do f(next())
```

#### Trait как интерфейсы с реализацией
До Java 8 интерфейсы не могли содержать реализации; трейты Scala всегда это позволяли. Они идеально подходят для отделения поведения, примешиваемого к различным классам, и для реализации паттерна «примесь» (mixin).

### Generics (Обобщения)

#### Обобщённые классы и методы
Классы и методы могут быть параметризованы типом, указываемым в квадратных скобках. Это позволяет писать обобщённый код, сохраняя типобезопасность.

```scala
class Box[A](val content: A)

def identity[T](x: T): T = x

val intBox = Box[Int](42)
val stringBox = Box("hello")  // тип выведен
```

#### Ограничения на типы: верхняя граница (`<:`), нижняя граница (`>:`)
- **Верхняя граница** `A <: B` — `A` должен быть подтипом `B`.
- **Нижняя граница** `A >: B` — `A` должен быть супертипом `B`. Используется реже, в основном в объявлениях ковариантных типов.

```scala
def max[A <: Ordered[A]](x: A, y: A): A = if x > y then x else y
```

Также есть ограничения по контексту (`using`/`given`) для type classes, но это выходит за рамки базовых дженериков.

#### Вариантность: ковариантность (`+`), контравариантность (`-`), инвариантность
- **Инвариантность** (по умолчанию): `Box[Cat]` не является ни подтипом, ни супертипом `Box[Animal]`, даже если `Cat <: Animal`.
- **Ковариантность** `+T`: `Producer[Cat]` является подтипом `Producer[Animal]`. Применяется к типам, которые только производят значения (выход). Например, `List[+A]`.
- **Контравариантность** `-T`: `Consumer[Animal]` является подтипом `Consumer[Cat]`. Применяется к типам, которые только потребляют значения (вход). Например, обработчики событий.

```scala
class Co[+A]      // ковариантный
class Contra[-A]  // контравариантный

val animals: Co[Animal] = Co[Cat]() // работает, если Co[+A]

val catConsumer: Contra[Cat] = Contra[Animal]() // работает, если Contra[-A]
```

В объявлении методов вариантность проверяется компилятором: в ковариантной позиции нельзя использовать `A` в контравариантной позиции (входные параметры) и наоборот.

#### Обобщённые типы в методах
Методы могут иметь собственные типовые параметры, не связанные с классом:

```scala
def singleton[A](a: A): List[A] = List(a)
```

Типовой параметр метода может иметь границы и контекстные ограничения.

### Модификаторы доступа

#### `private`, `protected`, `public` (по умолчанию)
- **Без модификатора** — член публичен (в отличие от Java).
- **`private`** — доступен только внутри класса или объекта, где объявлен.
- **`protected`** — доступен внутри класса и его подклассов.

```scala
class Counter:
  private var n = 0
  protected def increment(): Unit = n += 1
  def count: Int = n

class FastCounter extends Counter:
  def addTwo(): Unit =
    increment()
    increment() // protected доступен в подклассе
```

#### Область видимости `private[this]`, `protected[package]`
Scala позволяет уточнять область видимости с помощью `private[область]` или `protected[область]`.
- **`private[this]`** — доступ только из того же экземпляра (объектно-приватный).
- **`private[package]`** — доступ из указанного пакета и его подпакетов.
- **`protected[package]`** — аналогично, но дополнительно открыт для подклассов в указанной области.

```scala
package com.example.utils:
  class Util:
    private[utils] def helper = 42    // виден внутри пакета utils
    private[this] val secret = "hidden" // только внутри этого экземпляра
```

Объектно-приватный `private[this]` не порождает методов доступа, поэтому может быть более эффективен и гарантирует, что другой экземпляр того же класса не получит доступ.

### Пакеты и импорт

#### Объявление пакета, вложенные пакеты
Пакеты объявляются ключевым словом `package`. В Scala файл может содержать произвольное объявление пакета. Можно использовать вложенную нотацию.

```scala
package com.example.model

class User(val id: Long)
```

В Scala 3 можно писать:
```scala
package com.example:
  package model:
    class User(val id: Long)
```

Это сокращает необходимость повторного указания полного пути.

#### Импорт: одиночный, групповой, переименование, скрытие
Импорты гибкие:
- Одиночный: `import scala.collection.mutable.ListBuffer`
- Групповой: `import scala.collection.mutable.{HashMap, HashSet}`
- Всё из пакета: `import scala.math._`
- Переименование: `import java.util.{Random => JRandom}`
- Скрытие: `import scala.collection.mutable.{HashMap => _, _}` (импортировать всё, кроме HashMap)

Импорты можно размещать в любом месте кода (внутри методов, классов), а не только в начале файла.

```scala
def doMath(): Double =
  import scala.math.Pi
  Pi * 2
```

#### `import` внутри любого блока
Как показано выше, область действия импорта может быть ограничена блоком, что позволяет избежать конфликтов имён и делает код более читаемым.

### Объектная модель на JVM

#### Переопределение `equals`, `hashCode`, `toString`
В Scala рекомендуется использовать case-классы, где эти методы уже реализованы правильно. Но для обычных классов их можно (и нужно) переопределять, особенно если требуется структурное сравнение.

```scala
class Customer(val id: Long, val name: String):
  override def equals(other: Any): Boolean = other match
    case that: Customer => this.id == that.id && this.name == that.name
    case _ => false
  
  override def hashCode(): Int = (id, name).##
  
  override def toString: String = s"Customer($id, $name)"
```

#### Сравнение с Java-классами
- В Java статические члены принадлежат классу; в Scala — объекту-компаньону.
- В Java интерфейсы не могут иметь реализацию (до Java 8) и состояние; в Scala трейты могут содержать реализованные методы и поля.
- Модификаторы доступа: в Java по умолчанию пакетный доступ, в Scala — публичный.
- Перегрузка методов: Scala учитывает типы параметров и их количество, но не позволяет перегружать только по возвращаемому типу.
- В Scala нет ключевого слова `static`, нет оператора `new` для case-классов.
- Примитивы Scala (Int, Double) являются объектами с методами, но компилируются в примитивы JVM благодаря value-классам. Это стирает разницу между объектами и примитивами.

Эти различия обеспечивают более высокоуровневую и лаконичную работу с ООП, сохраняя полную совместимость с платформой JVM.
